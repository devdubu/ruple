# 공통 기반의 후속 필수 항목

2026-10-29 기준 작업 순서입니다. 두 트랙은 독립 환경에서 개발하고 API·계약으로 연결하는 소규모 MSA를 기준으로 합니다. 기술 스택·서비스 경계는 기존 AA를 유지합니다.

## 1. 백엔드 공통 규약·템플릿

공통 HTTP 기술 템플릿 v1을 적용했습니다. [백엔드 공통 규약](backend-conventions.md)과 `platform-http@1.0.0`에 적용 범위를 기록했습니다. 업무 공개 계약은 여전히 별도로 합의합니다.

- 완료: `/api/v1`·입력 검증·공통 오류·OpenAPI, 페이지 계약은 후속
- 완료: 서버가 확인한 신원과 검증기 연결 지점·개발 신원의 운영 차단. 실제 제공자·업무 권한은 후속
- 완료: 요청 식별·전파용 헤더·구조화 로그·민감정보 제외
- 완료: 환경변수 시작 시 검증·앱별 예시·명시적 주입 방식
- 🚧 시각·시간대·ID·리소스 버전·중복 요청·충돌 처리 원칙
- 🚧 외부 호출 timeout·취소·재시도, 기술 오류와 업무 실패의 구분
- 완료: liveness·readiness·기본 정상 종료. DB·모델 probe와 워커 진행 작업 처리는 후속
- 완료: 도메인별 Drizzle 설정·초기 migration·개발 DB 역할. outbox·pg-boss와 업무 테이블은 후속

Node 서비스 템플릿 하나에 먼저 적용하고 나머지 서비스에 반영합니다. AI API는 외부 오류·추적·인증 맥락 규약을 맞춥니다. 모듈별 알고리즘·테이블 상세·조건 판정은 담당자 설계로 남깁니다.

## 2. 프론트 기반

- 완료: 의미 기반 색상·타이포·간격·포커스·폰/차량 표시 토큰
- 완료: 버튼·입력·카드·대화상자·상태·재시도·개발 전용 미리보기
- 완료: TanStack Query·주입형 API·기술 계약 소비자 검증·취소·캐시 경계
- 완료: 화면 등록 계약·hash 경로·폰/차량 웹 표시 프로필
- 🚧 웹 셸·카드의 차량 호스트 최소 호환 시험

[프론트 공통 기반 v1](frontend-foundation.md)을 적용했습니다. 공통 UI는 제공하지만 업무 상세 화면·차량 호스트 적합성·Gen UI·실제 인증 연결은 후속입니다.

## 3. 독립 개발 환경

- 완료: 트랙별 로컬 개발 DB, 서비스별 역할·Drizzle migration·합성 데이터·초기화
- 완료: 기존 HTTP 기술 계약 기반 peer·AI 모의 서버. 추천·루틴·추론·차량 업무 예시는 계약 합의 후 추가
- 완료: 정상·인증 거절·충돌/만료 오류·오프라인·지연·잘못된 JSON·복구의 기술 시험. 실제 업무 상태 전이·빈 결과는 후속
- 완료: 주입형 Clock·고정 시각 이동 도구·seed/모의 헤더 적용. 도메인별 시간 판정 연결은 담당자 설계
- 완료: 공통 HTTP 기술 계약의 스키마·예시 검사와 Node·Python 응답 검증. 업무 계약의 생산자·소비자 검증은 후속

[독립 개발 실행 안내](isolated-development.md)에 시작·DB 소유권·시나리오·검증 명령을 정리했습니다. 기술 기반 준비와 업무 계약·통합 준비를 구분합니다.

## 4. 통합·배포 기반

- 🚧 시험 후보 → 표시 → 승인 요청 → 결과 표시의 최소 연결 예제
- 🚧 서비스별 ARM64 이미지와 검증된 커밋 SHA의 GHCR 게시
- 🚧 Ruple 전용 개발 namespace·Kustomize·Argo CD·라우팅·NetworkPolicy
- 🚧 지속 자료 적재 전 전용 저장소·백업·복원 검증
- 🚧 DGX Spark vLLM 호환·접근·부하 검증, 이후 RAG·실제 AI 호출

두 담당자가 기능 설계·개발을 시작할 수 있는 인계 기준은 공통 템플릿, 최소 UI 재료, 개발 DB, 계약 기반 대체 응답, 검증 명령과 개발 안내가 함께 작동하는 것입니다. 이번 작업공간 골격만으로 그 전체 준비가 끝났다고 판정하지 않습니다.
