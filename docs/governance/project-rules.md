# Ruple 프로젝트 공통 규칙

## 목적

서로 다른 개발자와 인공지능 도구가 작업하더라도 사용자에게 보이는 흐름, 모듈 입출력, 서비스 경계, 검증 근거가 흔들리지 않게 합니다.

## 우선순위

Ruple 저장소 안의 구현과 계약에는 이 문서와 `contracts/`가 공통 기준으로 적용됩니다. 개인 또는 도구별 규칙은 공통 기준보다 엄격하게 적용할 수 있지만 이를 완화하거나 다른 정본을 만들 수 없습니다.

충돌이 발생하면 자동으로 합치지 않습니다. 충돌한 규칙과 영향 범위를 제시하고 프로젝트 책임자의 판단을 받습니다.

## 필수 규칙

1. 요청 범위와 변경 파일을 먼저 확인합니다. 관련 없는 사용자 작업은 수정하거나 커밋하지 않습니다.
2. 모듈 내부 구현은 담당자가 정합니다. 다른 모듈이 의존하는 입력, 출력, 오류, 상태 전이는 `contracts/`에서 먼저 합의합니다.
3. 서비스는 다른 서비스의 소스나 데이터베이스를 직접 참조하지 않습니다. 연동은 공개 계약을 사용합니다.
4. 계약 변경에는 버전, 스키마, 정상 예시, 주요 오류 예시, 계약 검증을 함께 반영합니다.
5. 비밀정보, 개인식별정보, 운영 인증정보를 저장소에 커밋하지 않습니다.
6. 검증 결과에는 실행 명령, 대상 커밋, 통과 여부를 함께 남깁니다. 이전 커밋의 결과를 현재 결과처럼 사용하지 않습니다.
7. 미확정 사항은 추정하여 확정하지 않고 해당 위치에 `🚧`로 표시합니다.

## 변경 등급

| 등급 | 대상 | 처리 기준 |
|---|---|---|
| 모듈 내부 | 공개 계약에 영향이 없는 내부 로직 | 담당자 결정 후 테스트와 함께 반영 |
| 계약 | 입력, 출력, 오류, 이벤트, 상태 전이 | 계약 책임자 확인 후 버전과 예시 갱신 |
| 구조 | 서비스 경계, 배포 단위, 핵심 기술 선정 | 프로젝트 책임자 승인 후 아키텍처 문서 갱신 |

## 현재 기계 차단 범위

- 추적 대상 파일의 비밀정보 형태
- 필수 정본과 도구 어댑터 누락
- 서비스 간 명시적 소스 직접 참조
- 다른 업무 영역의 서버 패키지 직접 참조
- 등록 계약의 스키마 또는 예시 변경 시 버전 미갱신

상대 경로를 여러 단계 거치는 우회 참조와 실행 중 데이터베이스 연결 권한은 아직 정적 점검만으로 완전히 확인할 수 없습니다. Nx 작업공간과 실제 서비스가 생성되면 의존성 그래프 및 배포 권한 검사로 보완합니다.
