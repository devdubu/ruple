# Ruple 개발 하네스

Ruple 개발 하네스는 서로 다른 사람과 인공지능 도구가 같은 계약, 모듈 경계, 검증 기준을 따르게 하는 프로젝트 공통 장치입니다. 개인별 프롬프트와 작업 습관은 강제하지 않습니다.

## 구성

| 구분 | 정본 | 역할 |
|---|---|---|
| 프로젝트 규칙 | `project-rules.md` | 변경 금지선과 검증 기준 |
| 작업 흐름 | `workflow.md` | 계약부터 통합까지의 단계와 통과 조건 |
| 담당 경계 | `ownership.md` | 두 개발 트랙과 공동 변경 절차 |
| 계약 | `../../contracts/README.md` | 모듈 입출력과 버전 관리 규칙 |
| 기계 점검 | `../../harness/check.mjs` | 비밀정보, 필수 문서, 서비스 경계, 계약 정합 점검 |
| 도구 진입점 | `../../AGENTS.md`, `../../CLAUDE.md` | 공통 정본으로 연결하는 얇은 어댑터 |

## 적용 단계

1. 요청 단계: 로컬 점검을 권고하고 실패 원인을 수집합니다.
2. 측정 단계: 오탐과 누락을 보완합니다.
3. 차단 단계: 안정된 항목을 지속적 통합과 보호 규칙의 필수 점검으로 승격합니다.

현재 버전은 `0.1.0`입니다. 비밀정보 유출과 명시적 서비스 경계 위반은 즉시 차단하며, 계약 변경 검사는 계약 스키마가 등록되는 시점부터 작동합니다. 깃허브 저장소의 필수 점검 지정은 저장소 관리 설정에서 별도로 수행합니다.
