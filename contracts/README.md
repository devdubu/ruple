# Ruple 계약 관리

`contracts/`는 모듈과 서비스 사이에서 합의한 입력, 출력, 오류, 이벤트, 상태 전이의 정본입니다. 내부 구현 설명은 이곳에 두지 않습니다.

## 등록 순서

1. 사용자 흐름을 `flows/`에 기록합니다.
2. 흐름을 구성하는 모듈 경계를 식별합니다.
3. 각 경계의 스키마와 정상·오류 예시를 작성합니다.
4. `catalog.json`의 `contracts`에 식별자, 버전, 책임자, 스키마, 예시를 등록합니다.
5. 생산자와 소비자가 같은 예시를 기준으로 계약 검증을 작성합니다.

## 버전 규칙

- 버전은 `주버전.부버전.수정버전` 형식을 사용합니다.
- 호환되지 않는 필드 또는 의미 변경은 주버전을 올립니다.
- 호환되는 선택 필드 추가는 부버전을 올립니다.
- 설명 또는 예시 보정처럼 계약 의미가 바뀌지 않는 변경은 수정버전을 올립니다.
- 등록된 스키마나 예시가 바뀌었는데 버전이 그대로면 하네스가 실패합니다.

## 현재 상태

대표 출퇴근 흐름은 확정됐지만 각 경계의 필드 스키마는 아직 정하지 않았습니다. 따라서 `catalog.json`에는 흐름만 등록했고 `contracts`는 비어 있습니다. 필드가 합의되기 전에는 구현체가 임의의 공개 형식을 확정하지 않습니다.
