# 출퇴근 루틴 대표 흐름

## 확정 흐름

등록된 회사 정보와 평일 아침 반복 이동 근거를 바탕으로 출근 루틴을 제안하고, 사용자가 수정·승인하면 차량에서 길안내를 실행하고 상태를 표시합니다. 실제 도착 판정은 실행 시작과 분리합니다.

| 순서 | 모듈 | 입력 | 출력 | 상태 |
|---|---|---|---|---|
| 1 | M1 상황 수집 | 등록 회사 정보, 평일 아침 이동 관측 | 정규화된 상황 근거 | 흐름 확정, 필드 미정 |
| 2 | M2 상황 해석 | 상황 근거 | 출근 루틴 후보와 제안 근거 | 흐름 확정, 필드 미정 |
| 3 | M6 상호작용 | 루틴 후보 | 사용자 수정 또는 승인 결과 | 흐름 확정, 필드 미정 |
| 4 | M3 루틴 관리 | 승인된 루틴 | 저장된 루틴 정의 | 흐름 확정, 필드 미정 |
| 5 | M4 실행 판단 | 루틴 정의, 현재 상황 | 실행 가능 여부와 실행 요청 | 흐름 확정, 필드 미정 |
| 6 | M5 실행 오케스트레이션 | 실행 요청 | 차량 길안내 명령과 실행 상태 | 흐름 확정, 필드 미정 |
| 7 | M6 상호작용 | 실행 상태, 별도 도착 관측 | 사용자 상태 표시 | 흐름 확정, 필드 미정 |

## 상태 흐름

```text
관측 근거 수집
  -> 출근 루틴 후보 제안
  -> 사용자 수정·승인
  -> 루틴 저장
  -> 실행 판단
  -> 차량 길안내 시작
  -> 실행 상태 표시
  -> 실제 도착 별도 판정
```

## 구현 전 확정할 사항

- 🚧 각 단계의 필드, 자료형, 필수 여부
- 🚧 후보 수정 가능 항목과 승인 결과 형식
- 🚧 실행 직전 재확인 조건과 취소 정책
- 🚧 도착 판정에 사용하는 신호와 오차 처리
- 🚧 개인정보 보관 기간과 삭제 기준

위 항목이 확정되면 경계별 스키마와 예시를 만들고 `contracts/catalog.json`에 등록합니다.
