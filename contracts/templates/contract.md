# {{CONTRACT_ID}} 계약 작성 초안

- 상태: 🚧 초안, 공개 계약으로 등록되지 않음
- 검토 버전: `0.1.0`. 첫 공개 버전은 검토 후 결정
- 생산자·상태 소유 서비스: 🚧
- 소비 서비스·화면: 🚧
- 작성자 / 검토자 / 계약 책임자 확인 근거: 🚧
- 관련 흐름·요구사항: 🚧

## 목적과 경계

🚧 어떤 입력·출력 또는 상태 변경을 연결하는지 작성합니다. 다른 서비스의 내부 구조·DB 모델·알고리즘은 이 계약에 고정하지 않습니다.

## 인터페이스

| 항목 | 결정 내용 |
|---|---|
| 호출 또는 이벤트 | 🚧 방식·경로/종류·메서드. 이벤트면 발행자·구독자·전달 방식 |
| 입력·정상 출력 | 🚧 `schema.json`의 위치와 대응하는 valid 예시 이름 |
| 정상 응답 코드·접수 의미 | 🚧 저장·접수·처리 완료·전달 완료를 구분 |
| 인증·인가 | 🚧 검증된 신원에서 사용하는 범위와 리소스 소유권 검사 |
| 사용자·기기·차량 맥락 | 🚧 필요한 경우만 식별. 클라이언트 값의 검증 방법 |
| 조회·빈 결과·페이지 | 🚧 없음·접근 불가·실패·빈 목록·후속 페이지를 구분 |

## 필드 정의

🚧 필드마다 의미·자료형·필수 여부·생략과 null·단위·시간대·허용 범위·민감정보 여부를 적습니다. `not: {}`는 모든 입력을 거부하는 시작점입니다. 실제 스키마로 교체하고 정상·오류·거부 예시를 채우기 전에는 검증을 통과하지 않습니다.

## 변경·동시성·시간

| 항목 | 결정 내용 |
|---|---|
| 식별·연관 관계 | 🚧 리소스 ID와 요청 추적 ID의 구분 |
| 상태 소유권·전이 | 🚧 누가 어느 상태에서 어떤 상태로 변경하는지. 조회 전용이면 해당 없음과 근거 |
| 버전·충돌 | 🚧 비교할 버전, 오래된 입력, 경합 처리·재조회 방법 |
| 중복 요청·재전달 | 🚧 필요 여부, 키 범위·동일성·원자성·보존·재조회. 해당 없으면 근거 |
| 시각·유효기간 | 🚧 시각의 의미·판정 주체·Clock 사용·지연 도착. 기한 숫자를 임의로 넣지 않음 |
| 취소·응답 불명 | 🚧 취소 접수와 실제 취소, 응답 유실 뒤 상태 확인 구분 |

## 오류와 의존성

🚧 오류별 HTTP/전달 결과·공통 기술 오류 또는 업무 오류·재시도 가능 조건·소비자의 후속 행동·예시 이름을 작성합니다. 서버가 통제할 수 없는 실패를 완료로 해석하지 않습니다. 외부 호출은 timeout·취소 전파·재시도·중단 후 조회 방법을 명시합니다.

## 자료·운영 책임

🚧 저장 소유 서비스, 개인정보의 수집·이용·로그 노출 범위, 보존·삭제 결정 사항, 필요한 권한·외부 자원·migration·readiness·종료 처리를 작성합니다. 적용되지 않는 항목은 근거와 함께 제외합니다.

## 검증과 등록

```bash
pnpm contract:check {{CONTRACT_ID}}
```

- 정상·업무 오류·거부 예시를 합성 자료로 작성하고 생산자·소비자가 함께 사용
- 인증·소유권·동시 변경·중복·만료·취소·응답 유실 중 해당 항목의 의미 검증
- 미정 항목을 해결하거나 이번 계약 범위에서 제외한 근거 작성
- 양쪽 담당자 검토와 계약 책임자 확인 근거 기록
- 검토 후 정식 경로로 파일을 옮기고 ID·버전·owner·schema·example을 `contracts/catalog.json`에 등록
- 이 문서도 정식 계약 옆으로 옮기고 관련 흐름과 연결
- `pnpm check:contracts`·생산자/소비자 시험·하네스 통과 후 공개 타입·모의 경로 연결

스키마 검증 통과는 계약 승인이나 업무 상태 전이의 검증을 뜻하지 않습니다. 세부 절차는 `docs/development/contract-authoring.md`를 따릅니다.
